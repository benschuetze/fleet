# Inventory: what Fleet does on its own

Every place that writes a handoff, summarises a session or opens/restarts one without a click at that moment.
Status as of 4.0.0. The hooks that `install-hooks` writes to `~/.claude/settings.json` run the built
`dist/hook.cjs` of the checkout Fleet was installed from, so a change only acts once that checkout is built.

Thresholds come from `autoHandoff` in `config.json` (`server/handoff/settings.ts`) and `brake` (`server/core/brake.ts`);
defaults are given. Handoffs live in `<repo root>/HANDOFF.md` (excluded from git via `.git/info/exclude`), the
bookkeeping in `~/.claude-fleet/handoffs.json` (registry: who asked, fingerprint, delivered, opened).

| # | Where | Trigger | Threshold | What happens | Stored in | Changed in stage 1 |
|---|---|---|---|---|---|---|
| 1 | `request.ts` `onStop` (hook `Stop`) | end of a turn | 5-hour limit ≥ `limitPercent` (85 %), once per limit block; or context ≥ `contextPercent` (85 %) or ≥ `largeContextTokens` (400k), at most every 2 h per repo; `autoHandoff.enabled` | asks Claude (additionalContext) to write a handoff; the turn goes on (`status: working`) | `HANDOFF.md`, registry entry | no |
| 2 | `request.ts` `request` → `openIn` | same as 1, reason "context" | `clearAfter` (on) and context ≥ `clearMinTokens` (150k), and an opener is available | marks that a fresh session should open after the handoff | registry (`openIn`, `openWhy`) | no |
| 3 | `request.ts` `takeOpen` (hook `Stop`) | end of the turn after the handoff from 2 was written | within 30 min of the request (`OPEN_WINDOW`), only once (`openedAt`) | **opens a new session** (desktop app, VS Code or terminal) with a visible continue prompt; the old one is not closed | registry (`openedAt`, group, previous session) | no |
| 4 | `request.ts` `checkpoint` (hook `Stop`) | every end of a turn after a limit handoff was written | registry key `limit:…`, file unchanged since Fleet's fingerprint | appends/replaces the section "Stand nach dem letzten Turn (automatisch)" from the transcript (no model) | `HANDOFF.md`, registry (`sha`, `baseAt`) | no |
| 5 | `failure.ts` `onStopFailure` (hook `StopFailure`) | a turn broke off (rate limit, API error) | `autoHandoff.enabled`; not if a foreign or Claude-written handoff is younger than 2 h / one of ours was extended < 30 min ago | writes an **emergency handoff** from the transcript (prompts, todo list, files, commands), or an addendum to the same session's handoff | `HANDOFF.md`, registry key `failure:<time>` | **yes**: no invented next step "Letzten Auftrag fortsetzen …" when there is no todo list |
| 6 | `start.ts` `onSessionStart` (hook `SessionStart`, source startup/clear) | a new session starts in a repo with a handoff (≤ 7 days) | `autoHandoff.enabled`; content passed only if Fleet's fingerprint matches, otherwise only mentioned as data | delivers the handoff into the new session; asks it to move into the folder, into the sidebar group and to **rename** itself and the previous session ("· abgelöst …" / "· zusammengefasst …") | registry (`deliveredTo`, links) | no |
| 7 | `request.ts` `onPrompt` (hook `UserPromptSubmit`) | the next message after "Frisch starten" in the dashboard | a mark from the dashboard (`marks.ts`), even with `autoHandoff` off | asks for the handoff before anything else; 3 then opens the new session | `HANDOFF.md`, registry | no |
| 8 | `fresh.ts` `freshStart` (server, dashboard click) | "Frisch starten" while the session waits | Claude CLI logged in | **resumes the old session in the background** (`claude --resume <id> -p "Übergabe"`) so it writes the handoff; otherwise opens it for the user | `~/.claude-fleet` marks | no |
| 9 | `merge.ts` `mergeNow` (server, dashboard click on "Doppelt") | user merges duplicates | duplicate group not busy | builds a joint handoff from all transcripts (no model) | `HANDOFF.md`, registry (`merged`, `prevs`) | no (the duplicate group now needs a reason; see `groups.ts`) |
| 10 | `brake.ts` `onPreToolUse` → `requestNow` (hook `PreToolUse`) | 5-hour limit ≥ `brake.limitPercent` (95 %), checked at most every 20 s | waits `waitSeconds` (90 s) for an answer in the dashboard; **without an answer the session continues, no handoff** | only when the user picks "Übergabe schreiben": asks Claude for a handoff and stops | `HANDOFF.md`, registry key `brake` | no |
| 11 | `read.ts` `readHandoff` (server) | dashboard refresh | – | reads only; writes nothing | – | **yes**: adds `origin` (`claude` / `emergency`, from the registry key) |
| 12 | hook `PreCompact` | Claude Code compacts the context | – | only sets the status to `working`; no handoff, no summary by Fleet | `~/.claude-fleet/state/<id>.json` | no |
| 13 | `hooks/statusline.ts` | every status line refresh | – | stores context and limits for 1 and 10; writes no handoff, starts nothing (only runs a status line command the user had before) | `~/.claude-fleet/statusline/<id>.json` | no |
| 14 | `server/process/manager.ts` `job` via `fresh.ts` and `/api/job` (server, dashboard click) | "Frisch starten" while the session waits, or "Übergabe jetzt (Job)" on a finished session | Claude CLI logged in; no other Fleet process in that session (else 409); at most 2 jobs; 5-minute timeout | **resumes the session headless** (`claude --resume <id> -p … --output-format stream-json --permission-mode acceptEdits --max-turns 4`); replaces the detached spawn of 8 when the server runs | `~/.claude-fleet/jobs.jsonl` (exact tokens and cost from the result line, `null` when missing) | stage 3 |
| 15 | `request.ts` `takeOpen` + `server/process/pending.ts` | end of the turn after a fresh-start handoff with target `fleet` | `runtime.json` says `terminal: true`; root must be a repo of the overview | the hook only sets `pendingStart`; the **server starts the new session in its own window** once, with the continue prompt | registry (`pendingStart`, `pendingPrompt`, cleared when taken) | stage 3 |
| 16 | `server/process/manager.ts` `restore` | server start | entries in `processes.json` from the last run | nothing is restarted: sessions that ran in Fleet's window stand as "interrupted" with "Fortsetzen" | `~/.claude-fleet/processes.json` | stage 3 |
| 17 | `server/core/fleetturns.ts` `beginTurn`/`endTurn` (hook `Stop`, `SessionStart`; `request`/`requestNow` in 1, 7, 10, 14; delivery in 6) | Fleet asks for a handoff, a session receives Fleet's handoff, or Fleet started it for a fix or briefing (`CLAUDE_FLEET_TURN`) | – | **only writes marks** for the Fleet balance (begin, end at the next Stop); starts nothing, tells Claude nothing | `~/.claude-fleet/fleet-turns.jsonl`, `~/.claude-fleet/turns/<id>` while open | stage 5 |
| 18 | `start.ts` `onSessionStart` (hook `SessionStart`, together with 6) | a new session receives Fleet's handoff (also a merge from 9) | `autoHandoff.enabled` and `autoHandoff.archivePredecessor` (on); only predecessors Fleet recorded with a desktop-app id (`prev`, `prevs` for a merge); tool `mcp__ccd_session_mgmt__archive_session` present, otherwise skipped (terminal, VS Code) | asks the new session to **archive the replaced session(s)** after renaming them, silently, never itself or any other session | desktop app (archive); Fleet stores nothing new | unreleased |

Other hook changes in stage 1, none of which writes a handoff or starts a session: `Stop` stores the last 400
characters of the answer (`lastAnswer`) in the state file; `StopFailure` writes `error: error_details` as detail;
`Notification` `quota_auto_resume_fired` keeps the status.
